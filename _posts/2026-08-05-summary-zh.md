Simon Willison 于 2026 年 8 月 4 日发布 LLM 0.32，这是该项目启动以来最重要的版本，带来可见推理痕迹、服务端工具、OpenAI Responses API 支持以及重新设计的内容寻址 SQLite 日志。CLI 现在会把推理模型的思考过程输出到标准错误，可用 -R/--hide-reasoning 关闭；内置 GPT-5.6 模型家族，默认模型改为 GPT-5.6 Luna。新增服务端工具，例如 OpenAI 的 CodeInterpreter 与 WebSearch，llm-anthropic 0.26 插件则加入 WebSearch、WebFetch、CodeExecution 和 AnthropicMCP。新的 \`llm openai endpoint\` 命令可不经配置直接调用任何 OpenAI 兼容端点，且不写入日志。Python API 新增 \`model.prompt\(messages=\[\]\)\` 与 \`stream\_events\(\)\`，以处理推理文本、输出字符串、工具调用和图片附件混合返回。

rss · Simon Willison · 8月4日 23:58

**「背景」** LLM 是 Simon Willison 开发的命令行工具和 Python 库，通过插件支持多种模型提供商，并以 SQLite 存储对话日志。此前 Python API 要求先创建 conversation 再逐条发送消息，且 prompt 只返回字符串序列；0.32 改成直接传入完整消息历史并支持结构化事件流，以匹配现代模型混合返回的形态。

**「影响」** 使用 LLM CLI 的开发者现在可以直观查看推理过程、直接调用服务端工具，并无需预先配置即可对任意 OpenAI 兼容端点运行一次性提示；Python 开发者则可以基于完整消息历史和事件流构建更复杂的多轮、工具调用和流式应用。

Monodratic 是一种使用学习式乘积哈希路由的稀疏因果注意力架构，由独立研究者提出。其思路是在 RoPE 之后将源块分配到有界因果发布列表，查询通过乘积地址探查、重排序并选择固定数量的远程块，加上本地块后进行精确因果 softmax。实验显示，在学习路由、固定远程块预算下，关联召回准确率达 99.35%（平均值）或 98.05%（最低值），而同等宽度的未训练路由器和仅本地注意力分别只有 425/768 和 151/768 正确；强制加入目标块后可达 768/768。稀疏选择集注意力与独立稠密选择掩码 oracle 的最大绝对误差为 1.43e-6；打包 CPU 实现在 4,096 到 32,768 个 token 下拟合时间指数为 0.993，且所有学习路由和扩展运行均未出现发布溢出。局限是实验为合成数据、实现为可移植 PyTorch 而非融合 kernel，且不声称自然语言质量、渐近线性构建或部署速度。

reddit · r/MachineLearning · /u/dttdrv · 8月5日 10:28

**「背景」** 标准自注意力的计算量随序列长度二次增长，稀疏注意力为此只对选定的一部分 token 对执行注意力计算。Monodratic 属于稀疏注意力路由一类方法：它利用乘积哈希将 key 块分配到有界的因果发布列表，查询以固定预算挑选少量远端源块并保留局部块，再对这些 token 执行精确 softmax。关联回忆（associative recall）任务常用于测试模型能否检索并利用输入中先前出现的键值对应关系，因此实验以该任务衡量路由质量。

**「影响」** 研究人员可据此验证：在合成的关联回忆任务中，学习型乘积哈希路由能以固定远端块预算实现 99.35%的平均准确率（三种子最低 98.05%），并在 CPU 上呈现近线性缩放（拟合指数 0.993），但该结论仍限于合成实验与便携 PyTorch 实现，尚未覆盖自然语言质量、融合内核或部署性能。
