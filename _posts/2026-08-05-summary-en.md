### [LLM 0.32 adds reasoning traces, server-side tools, and Responses API support](https://simonwillison.net/2026/Aug/4/new-release-of-llm/#atom-everything) ⭐️ 8.0/10

Simon Willison released LLM 0.32, described as the most significant version since the project&\#x27;s launch. The update adds visible reasoning traces that are written to standard error \(with a -R/--hide-reasoning flag to suppress them\), built-in support for the GPT-5.6 model family with GPT-5.6 Luna as the new default, and server-side tools such as OpenAI&\#x27;s CodeInterpreter and WebSearch. The llm-anthropic plugin 0.26 also adds WebSearch, WebFetch, CodeExecution, and AnthropicMCP tools. A new \`llm openai endpoint\` command lets users run one-off prompts against any OpenAI-compatible endpoint without logging, and the Python API now supports \`model.prompt\(messages=\[\]\)\` plus a streaming events interface for reasoning, text, and tool-call events. The release also includes redesigned content-addressable SQLite logs and new models.

rss · Simon Willison · Aug 4, 23:58

**「Background」** LLM is a command-line tool and Python library for interacting with large language models, using plugins to support different providers. Previously, the Python API required creating a conversation and sending messages one at a time, and prompts returned only iterable sequences of strings, which did not handle modern models&\#x27; mixed reasoning, tool calls, and image attachments. This release adapts to those evolving model outputs and adds direct access to provider-hosted tools and external endpoints.

**「Impact」** Developers using the LLM CLI can now keep reasoning traces out of piped stdout while inspecting them on stderr, and can invoke provider-hosted tools like code execution or web search without extra client-side setup. ### [ChainDrop Worm Hits Over 1,300 npm Packages](https://www.bleepingcomputer.com/news/security/massive-chaindrop-npm-supply-chain-attack-infects-hundreds-of-packages/) ⭐️ 8.0/10

The self-propagating ChainDrop worm has compromised more than 1,300 npm packages, totaling 2 billion monthly downloads, including the popular cache libraries Keyv and Cacheable. The attack began when a hacker took over a Keyv maintainer&\#x27;s GitHub account and spread to packages tied to Deliveroo, Qlik, and ServiceTitan; malicious versions were published through normal GitHub Actions workflows with valid provenance. During npm install, a setup.mjs dropper and a Math\_Symbol.js credential-stealing script execute automatically, harvesting GitHub, npm, AWS, Kubernetes, and other credentials while infecting additional maintainers&\#x27; packages. Security vendors advise that anyone who installed an affected version should treat the system as compromised, rebuild the environment, rotate all tokens, and check logs, with npm-cache\[.\]com as an indicator of compromise. The attack is still spreading, and the number of affected packages is expected to grow.

telegram · zaihuapd · Aug 5, 03:04

**「Background」** npm is the default package manager for JavaScript and the largest software registry, where packages are often installed automatically by developers&\#x27; tooling. In a supply-chain attack, cybercriminals compromise a trusted maintainer&\#x27;s account and publish malicious versions of legitimate packages. In the ChainDrop campaign, attackers took over the GitHub account of the Keyv maintainer, added a preinstall script plus setup.mjs and Math\_Symbol.js to the repository, and pushed malicious versions through the normal GitHub Actions workflow, giving them valid provenance; the scripts execute during npm install and steal credentials.

**「Impact」** Affected developers and organizations must treat any system that ran npm install with a poisoned package as fully compromised and immediately rebuild environments and rotate GitHub, npm, AWS, and Kubernetes credentials.

### [Monodratic: Learned Product-Hash Routing for Sparse Causal Attention](https://www.reddit.com/r/MachineLearning/comments/1vg3jda/monodratic_learned_producthash_routing_for_sparse/) ⭐️ 7.0/10

Independent researcher /u/dttdrv released Monodratic, a sparse causal-attention architecture that uses learned product-hash routing to assign query and key blocks after RoPE and runs exact softmax over a fixed set of remote plus local blocks. In synthetic associative-recall tests with two selected remote blocks out of five eligible, the learned router got 763/768 correct across three seeds \(99.35% mean, 98.05% minimum\), versus 425/768 for an untrained router and 151/768 for local-only attention; forcing the labeled target block within the same budget corrected the remaining five errors. The sparse selected-set attention matched a dense oracle within 1.43e-6 maximum absolute error, and the packed CPU router had a fitted timing exponent of 0.993 over 4,096 to 32,768 tokens with zero posting overflow. The author notes limitations: experiments are synthetic, implementation is portable PyTorch rather than a fused kernel, and no claims are made about natural-language quality, asymptotic linear construction, or deployment speed.

reddit · r/MachineLearning · /u/dttdrv · Aug 5, 10:28

**「Background」** Sparse attention mechanisms reduce the quadratic cost of full attention by computing only a subset of token interactions, often using fixed patterns or learned routing. Monodratic builds on this idea with product-hash routing: after applying rotary position embeddings \(RoPE\), source blocks are assigned to bounded causal posting lists, and each query probes a small number of product addresses to select remote blocks, then runs exact softmax over the selected tokens. Associative recall is a common synthetic benchmark for such architectures because it tests whether the model can retrieve a previously stored key-value pair, which depends heavily on effective attention routing.

**「Impact」** The concrete upshot for researchers building sparse-attention architectures is that learned product-hash routing can preserve dense-attention associative-recall behavior \(763/768 correct, 99.35% mean\) with a fixed remote-block budget of only 2 selected remote blocks out of 5 eligible, while the packed CPU implementation shows near-linear scaling \(fitted timing exponent 0.993\) and zero posting overflow; however, these gains are not yet a deployable speedup or a natural-language quality claim because the implementation is portable PyTorch rather than a fused kernel.
